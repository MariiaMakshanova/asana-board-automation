# Asana Board Automation

![tests](../../actions/workflows/tests.yml/badge.svg)

Инструмент на **Node.js + Playwright**, который создаёт задачи на канбан-доске Asana через интерфейс, как это делал бы человек:
колонка → «Добавить задачу» из шаблона → название → (опционально) кастомные поля, описание, исполнитель.

Перед открытием браузера данные для названий задач (бренд и гео по домену) **проверяются через REST API CRM**.
Если данные противоречат друг другу, запуск останавливается и в продакшен-доску ничего не пишется.

> Это обезличенная демо-версия рабочего инструмента. Все домены, бренды и данные CRM вымышлены,
> ссылки на проекты и ключи задаются только через `.env`.

## Что внутри

| Часть | Что показывает |
|---|---|
| `src/asanaTaskManager.js` | UI-автоматизация: `getByRole`/CSS-локаторы с запасными вариантами, ожидания, повтор попыток, восстановление после сбоя, проверка, что страница осталась в нужном проекте |
| `src/crmLookup.js` | REST-клиент: POST + JSON-фильтры, пагинация, авторизация `X-API-Key`, таймауты, понятные сетевые ошибки |
| `src/crmCheck.js` | Валидация данных до запуска UI: CRM — источник истины, локальный справочник — помеченный fallback, конфликт блокирует запуск, CSV-отчёт |
| `src/titleFormatter.js` | Парсинг входных строк (URL, `[url]`, markdown-ссылки), гео из пути URL |
| `mock/crmMockServer.js` | Локальный мок CRM API с тем же контрактом (ключ, пагинация, коды ошибок) |
| `tests/` | Юнит- и интеграционные тесты на `node:test`, запускаются в GitHub Actions |

## Архитектура

```
input/*.txt ──► parseInput ──► домены ──► CRM API (+ fallback lookup)
                                             │
                     конфликт / нет данных ◄─┤──► отчёт reports/crm_check_*.csv
                     (стоп, браузер не стартует)
                                             ▼
                           названия задач ──► Playwright (Chromium) ──► Asana board
                                                                  └──► reports/created_*.csv (ссылки)
```

Сценарии описываются конфигом (`src/taskConfigs.js`): проект, колонка, шаблон задачи, парсер входа.
Новый сценарий добавляется без изменений движка.

## Запуск

```bash
npm install
npx playwright install chromium
cp .env.example .env            # вписать ASANA_PROJECT_URL

npm test                        # тесты (браузер и сеть не нужны)

npm run mock:crm                # в отдельном терминале — фейковый CRM на :4010
LOOKUP_FILE=data/lookup.example.json npm run format   # dry-run: только названия, без Asana

npm run auth                    # один раз войти в Asana вручную (сессия хранится в user-data/, в git не попадает)
npm start                       # меню сценариев → создание задач на доске
```

## Безопасность

- Секреты и ссылки на проекты — только в `.env` (в `.gitignore`), в репозитории есть только `.env.example`.
- Сессия браузера (`user-data/`), отчёты (`reports/`) и реальный справочник (`data/lookup.json`) не коммитятся.
- Dry-run (`npm run format`) позволяет проверить результат без изменений в Asana.
